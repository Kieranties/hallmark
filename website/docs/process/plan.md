# Plan

**Write the actions, in order.** One question: *how will it be actioned?* Sub-items are fine,
and so is discovering that the answer is longer than expected.

**A plan is revisable, and revising it is not failure.** It is a route, not a promise; the
promise was made elsewhere — on the [commitment](../work/commitment.md) axis — and is not
renegotiated by discovering the route is longer.

## Touch

**Touch is what a change reaches** — the parts of the system it alters, and whatever depends
on them. **Declared by the plan**, because listing what will change has already listed what is
reached.

**Touch decides what a change must satisfy.** The wider it reaches, the more
[standards](../work/standards.md) come into scope. That is derived from the change itself,
never judged: nobody rules a change small enough to skip something.

> **Done when:** the actions are ordered, and the touch is declared.
>
> **Verified when:** someone who did not write it confirms that following it would make the
> [specifications](./specify.md) pass. If it might not, the plan is not finished.
