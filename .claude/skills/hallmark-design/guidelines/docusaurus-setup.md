# Applying this system to the Docusaurus site

Nothing here needs swizzling. Five steps, all inside `website/`.

## 1. Copy the tokens in

Copy this project's `tokens/` directory to `website/src/css/tokens/`, then replace the body of
`website/src/css/custom.css` with import lines:

```css
@import "./tokens/fonts.css";
@import "./tokens/colors.css";
@import "./tokens/typography.css";
@import "./tokens/spacing.css";
@import "./tokens/borders.css";
@import "./tokens/elevation.css";
@import "./tokens/motion.css";
@import "./tokens/docusaurus.css";       /* maps brand tokens onto Infima */
@import "./tokens/docusaurus-theme.css"; /* must stay last — fixes what variables cannot reach */
```

`docusaurus.css` sets `--ifm-color-primary`, the three font families,
radii, navbar/footer colours, table and admonition colours.

`docusaurus-theme.css` handles the three things Infima variables **cannot** reach, because Infima
declares them inside its own selectors:

1. **Footer colour** — the footer is the same dark slab in both themes, so it cannot use the ink
   ramp (which inverts) or Infima's footer variables (`.footer--dark` redeclares them `#303846`).
   Fixed `--hm-footer-*` tokens are applied to `.footer` directly.
2. **Alignment** — navbar, page content and footer all resolve to `--hm-page-max`, so their left
   edges line up on every page. The footer logo is pulled left; Docusaurus centres it by default.
3. **Navbar icons** — the GitHub link is theme text and the colour-mode toggle uses Infima's own
   glyph, so they never matched. Both are masked Lucide icons at 19px, one stroke weight. This
   requires `className: 'header-github-link'` and **no** `label` on the navbar item.

It also carries the chrome the variables miss: sidebar active edge, breadcrumbs, pagination,
admonitions, tabs, table headers, focus ring. Keep it last.

The scaffold's green/teal
`:root` and `[data-theme='dark']` blocks in the old `custom.css` should be deleted — the token
files carry both themes.

Docusaurus bundles `custom.css` with its own CSS pipeline, so relative `@import`s resolve. Fonts
load from `fonts.googleapis.com` via the `@import` in `tokens/fonts.css`.

Optional, for a faster first paint — preconnect in `docusaurus.config.ts`:

```ts
headTags: [
  {tagName: 'link', attributes: {rel: 'preconnect', href: 'https://fonts.googleapis.com'}},
  {tagName: 'link', attributes: {rel: 'preconnect', href: 'https://fonts.gstatic.com', crossorigin: 'anonymous'}},
],
```

## 2. Add the brand assets

Copy `assets/logo-mark.svg`, `logo.svg`, `logo-dark.svg`, `favicon.svg` and `punch-grid.svg`
into `website/static/img/`, then in `docusaurus.config.ts`:

```ts
favicon: 'img/favicon.svg',
themeConfig: {
  navbar: {
    title: 'Hallmark',
    logo: {alt: '', src: 'img/logo-mark.svg', width: 26, height: 28},
    ...
  },
  footer: {style: 'dark', ...},
}
```

The footer is already `style: 'dark'`, which the bridge paints `--hm-ink-900`.

## 3. Use the theme features the components mirror

Every component in this system maps onto something the classic theme already renders — author in
MDX and the styling follows:

| This system | Docusaurus |
| --- | --- |
| `Callout` | `:::note` / `:::tip` / `:::info` / `:::warning` / `:::danger` |
| `TabbedPanel` | `<Tabs>` / `<TabItem>` |
| `CodeBlock` | fenced code blocks (` ```yaml title="…" `) |
| `DocCard` | `<DocCardList>` and generated index pages |
| `DocPager` | built-in pagination |
| `SidebarNav` | the autogenerated sidebar |
| `Breadcrumbs` | built-in breadcrumbs |
| `DataTable` | markdown tables |

## 4. Add the two components the theme has no equivalent for

`StateChip` and `Badge` are Hallmark-specific. Port them as MDX components:

1. Create `website/src/components/StateChip.tsx` and `Badge.tsx`, copying the JSX from
   `components/docs/StateChip.jsx` and `components/core/Badge.jsx` — they are plain React reading
   CSS custom properties, so the only change is adding types.
2. Register them globally with a hand-written `src/theme/MDXComponents.tsx` that re-exports the
   classic theme's map plus the two additions. This is not a swizzle, so theme upgrades never
   conflict:

   ```tsx
   import MDXComponents from '@docusaurus/theme-classic/lib/theme/MDXComponents';
   import Badge from '@site/src/components/Badge';
   import StateChip from '@site/src/components/StateChip';
   export default {...MDXComponents, Badge, StateChip};
   ```

   Any `.md` file can then use `<StateChip state="verified" />` with no import.

`Icon` fetches from the Lucide CDN so the mocks in this project run without a build. On the real
site use `lucide-react` (`npm install lucide-react --prefix website`) at `strokeWidth={1.75}`.

## 5. Landing page

`website/src/pages/index.md` currently renders as a plain doc. To get the hero from
`ui_kits/docs-site/LandingPage.jsx` (punch-grid field, Spectral display, two buttons, state strip),
convert it to `index.tsx` using `@theme/Layout` and copy the markup across — the copy is already
verbatim from the markdown version.

## Checking it worked

`npm run start --prefix website`, then confirm: headings are Spectral, links are madder
`#8A2F1C`, inline code is warm grey not blue-grey, admonitions carry the metal palette, the footer
is near-black brown (**not** blue-grey) with its left edge aligned to the content above it, the two
navbar icons match in size and stroke weight, and toggling dark mode gives a brown-black page with
terracotta links.

## Keeping it in sync

`website/src/css/tokens/` and `website/static/img/` are **generated**. Change tokens and assets in
the design system, then re-copy; never hand-edit the site copies. If the site does drift, ask the
design agent to sync from the repo so `github.md`'s screen map stays honest.
